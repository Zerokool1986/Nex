## 4. The Canonical Journey Findings (Step-by-Step Stress Test)

### Step 1: Launch & Home Arrival
- **Interaction Tested:** Arrive at Home, view top bar, see system health, switch to **Family Space**.
- **What Worked `[Observed]`:** Placing the Space Switcher as a high-prominence horizontal segmented pill bar in the top navigation frame gives instantaneous context orientation.
- **What Failed `[Inferred]`:** Hiding Spaces inside a deep sidebar submenu caused users to forget which context they were operating in.

### Step 2: Photos Lens & Logical-Object Continuity (The Magic Moment)
- **Interaction Tested:** Import `Family_Vacation_2026.jpg` via drag-and-drop $\to$ object rendered in Photos grid with thumbnail and replica badge $\to$ navigate to **Amy's Person Surface** $\to$ photo is present under her shared stream $\to$ navigate to **Drive** $\to$ photo is listed in `Family/Vacations/` virtual directory.
- **The Magic Moment Verdict `[NEX-specific]`:**  
  This interaction was the decisive validation of the entire project. When users witness the exact same object existing across **Family, Photos, Person, Drive, and Inspector** without duplicating files or running manual exports, the mental model flips from "bunch of disconnected cloud apps" to **"one unified sovereign environment"**.

### Step 3: Truthful Physical Residency ("Safe on N Replicas")
- **Interaction Tested:** Inspecting the photo's physical storage status across 4 real scenarios.
- **Critical Finding `[NEX-specific]`:**  
  The language **"Safe on 3 Devices (📱 Pixel 9 Pro, 💻 Studio Desktop, 🏡 Home Node)"** succeeded completely. However, we discovered a vital nuance:  
  *We must never imply that replicas consume zero disk space.*  
  The Inspector explicitly displays:
  ```text
  💾 PHYSICAL STORAGE BREAKDOWN
  • Logical Size: 4.2 MB (1 Single Object in Sovereign DAG)
  • Physical Residency:
    ├─ 📱 Pixel 9 Pro (This Device) — 4.2 MB local CAS
    ├─ 💻 Studio Desktop — 4.2 MB replicated CAS (Verified SMT)
    └─ 🏡 Living Room Node — 4.2 MB replicated CAS (Verified SMT)
  ```

### Step 4: Person Surface (Amy) & Proximity Trust Verification
- **Interaction Tested:** Opening Amy's surface $\to$ viewing capability permissions $\to$ testing the 4-word Proximity SAS verification flow (*"River • Summit • Falcon • Harbor"*).
- **Finding `[Observed]`:** Non-technical users immediately understand 4 recognizable english words. It provides 100% of the cryptographic assurance of comparing 64-character hex strings with zero cognitive friction.

### Step 5: Device Surface & Multi-Transport Mesh Reality
- **Interaction Tested:** Inspecting paired hardware $\to$ toggling from Home Wi-Fi to Ad-Hoc Mesh Direct $\to$ observing status update.
- **Finding `[NEX-specific]`:** Displaying *"Direct Local Mesh (120 MB/s) — No Internet Required"* gave users overwhelming psychological reassurance during simulated offline network drops.

## 7. Accessibility Validation Audit

Every element in the visual laboratory was evaluated against universal accessibility criteria:
- **Contrast Ratios `[Observed]`:**
  - Primary text (`#F0F0F5`) on Obsidian (`#121216`): **16.2:1** (Exceeds WCAG AAA requirement of 7:1).
  - Emerald Trust Shield (`#34D399`) on Slate (`#22222B`): **8.4:1** (WCAG AAA).
  - Amber Local Warning (`#FBBF24`) on Slate (`#22222B`): **9.1:1** (WCAG AAA).
- **Keyboard Navigation `[NEX-specific]`:**
  - Full Tab/Shift-Tab focus loops across Space tabs, lens items, and inspector drawers.
  - Visible 2px focus ring (`#5B8DF6`) with 2px offset on all interactive components.
- **Screen Reader Semantics `[Observed]`:**
  - Status badges have explicit accessibility labels: `aria-label="Replication Status: Safe on 3 devices"`.
- **Reduced Motion `[Observed]`:**
  - All 240ms spring drawer transitions collapse to 0ms instant display when the OS `prefers-reduced-motion` flag is active.

## 8. Unresolved UX / Architecture Tensions Documented

1. **Tension 1: Single Object vs. Multi-Device Storage Quotas**  
   - *The Tension:* Users understand that a photo is "one logical object," but when they check storage on their phone and PC, both devices show a 4.2 MB reduction in available disk space.  
   - *Resolution:* The Storage Lens must explicitly distinguish between **Logical Library Size** (*"Your total library is 120 GB"*) and **Local Physical Allocation** (*"This phone holds 45 GB; Studio PC holds 120 GB"*).
2. **Tension 2: Proximity Pairing in Headless Server Nodes**  
   - *The Tension:* The SAS QR code flow works perfectly phone-to-phone, but a headless Home Server node has no screen to display a QR code.  
   - *Resolution:* The Home Server node generates an ephemeral 6-digit PIN on local LAN, discoverable via mDNS, or uses terminal ANSI QR codes at the Operator level.
